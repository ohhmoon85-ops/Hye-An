기획 요약

이미 축적된 253건의 전략 분석 문건을 “폴더”가 아니라 “발행물”로 바꾸는 일입니다. 핵심은 새 콘텐츠를 만드는 것이 아니라, 있는 자산에 발견 가능성·신뢰 표식·과금 경로를 입히는 것입니다.

이 플랫폼이 파는 것

안보·국제정세 정보는 공짜로 넘칩니다. 사람들이 돈을 내는 지점은 정보가 아니라 판단입니다. 30년 야전·정책 경력을 가진 특정 개인이 “이 사안은 이렇게 읽어야 한다”고 이름을 걸고 말해주는 것 — 이것이 유일한 방어 가능한 상품입니다. 따라서 사이트의 모든 설계는 익명의 자료실이 아니라 기명(記名)의 판단을 향합니다.

설계 원칙 4

  1. 기명성 — 모든 문건에 저자·작성일·근거자료를 명시한다. 익명 요약본은 만들지 않는다.
  2. 계층 공개 — 핵심 요약은 무료로 완전 공개, 본문·원자료·슬라이드는 구독. 검색엔진에는 요약이 노출되어야 유입이 생긴다.
  3. 축적의 가시화 — 253건이라는 규모 자체가 신뢰 자산이다. 아카이브 규모와 시계열을 첫 화면에서 보여준다.
  4. 단순한 뼈대 — 기능을 늘리지 않는다. 읽기·검색·결제 세 가지만 흠 없이 동작하면 된다.

Next.js(App Router) + Vercel + Supabase. 서버를 직접 운영하지 않고, 콘텐츠 보호에 필요한 판단만 서버에서 수행하는 구조입니다.

그림 1 — 요청 흐름. 본문 권한 판정은 반드시 서버(Server Component)에서 수행한다.

선택 근거

결정이유
Vercel Pro 필수 ($20/월)Hobby 플랜은 상업적 이용이 허용되지 않습니다. 유료 서비스는 개설 시점부터 Pro여야 합니다. 대역폭 1TB/월 포함.
Supabase Pro ($25/월)Free는 DB 500MB·스토리지 1GB로 PDF 수백 건을 감당하지 못합니다. Pro는 스토리지 100GB, 대역폭 250GB 포함(초과 GB당 $0.09).
본문은 DB에, 첨부는 Storage에본문을 PDF로만 두면 페이월도 검색도 불가능합니다. 본문은 Markdown으로 documents.body_md에 저장하고, 원본 PDF·PPTX는 비공개 버킷에 둡니다.
App Router + RSC권한에 따라 본문을 보낼지 말지를 서버에서 결정합니다. 클라이언트에서 CSS로 가리는 방식은 개발자도구로 즉시 뚫립니다.

데이터 모델

테이블 8개면 충분합니다. 구독 상태를 문건 접근 권한과 직접 연결하지 않고 entitlements 한 겹을 두는 것이 핵심 — 나중에 기관 라이선스·무료 체험·기자단 계정을 코드 수정 없이 얹을 수 있습니다.

profiles          id(uuid, =auth.users) · email · name · org · role(reader|admin) · created_at

categories        id · slug · name_ko · name_en · sort_order

documents         id · slug · title · subtitle · category_id
                  summary_md      무료 공개 — 검색엔진 색인 대상
                  body_md         유료 본문 — 권한 통과 시에만 전송
                  doc_type        brief | report | archive | series
                  rights_tier     A | B | C | D  (§04 공개 등급)
                  access_level    free | member | institution
                  published_at · free_until · source_path · tags[] · view_count

attachments       id · document_id · storage_path · kind(pdf|pptx|hwpx|image)
                  filename · bytes · is_public

plans             id · code(free|member_m|member_y|inst) · price_krw · period · seats

subscriptions     id · user_id · plan_id · status(active|past_due|canceled)
                  billing_key · current_period_end · canceled_at

entitlements      id · user_id · scope(all|category|document) · scope_id
                  source(subscription|institution|grant|trial) · expires_at
                  ↑ 권한 판정은 오직 이 테이블만 조회한다

                  status · paid_at · receipt_url

RLS 정책 (핵심 3개)

-- 1. 요약은 누구나, 본문은 권한자만
create policy "doc_read" on documents for select using (
  published_at <= now()
);
-- body_md는 SELECT 컬럼 권한을 회수하고, 서버에서 SECURITY DEFINER 함수로만 조회
revoke select (body_md) on documents from anon, authenticated;

-- 2. 열람 권한 판정 함수 (서버 전용)
create function get_document_body(doc_slug text)
returns text language plpgsql security definer as $$
begin
  if exists (select 1 from entitlements e
              where e.user_id = auth.uid()
                and (e.expires_at is null or e.expires_at > now())
                and (e.scope = 'all' or e.scope_id = ...))
  then return (select body_md from documents where slug = doc_slug);
  end if;
  return null;
end; $$;

-- 3. 본인 결제·구독만 조회
create policy "own_rows" on subscriptions for select
  using (user_id = auth.uid());
흔한 실수. 본문을 클라이언트로 다 보낸 뒤 blur나 max-height로 가리는 구현이 많습니다. 개발자도구 한 번이면 전문이 드러납니다. 반드시 서버에서 본문을 아예 응답에 담지 않는 방식이어야 합니다.
09

콘텐츠 보호

완벽한 복제 방지는 불가능합니다. 목표는 대량 유출을 어렵게 하고, 유출 시 출처를 특정하는 것입니다.

  1. 비공개 버킷 원칙Supabase Storage 버킷을 private로 두고 공개 URL을 절대 생성하지 않습니다. 파일 접근은 /api/files/[id]를 거쳐 권한 확인 후 유효기간 60초 Signed URL을 발급합니다.
  2. 개인화 워터마크PDF 다운로드 시 Edge Function이 각 페이지 하단에 혜안 · 홍길동(hong@corp.kr) · 2026-09-01을 삽입합니다. 유출본이 돌아다니면 누구 계정에서 나갔는지 즉시 특정됩니다. 억지력이 실제 차단보다 큽니다.
  3. 다운로드 한도계정당 일 20건·월 100건. 초과 시 자동 차단 후 관리자 알림. access_logs의 ip_hash로 계정 공유(동시 다중 IP)를 탐지합니다.
  4. 본문 서버 렌더§08의 원칙대로 권한 없는 요청에는 본문을 응답에 담지 않습니다. HTML 소스에도 남지 않습니다.
  5. 검색엔진 정책요약(summary_md)은 색인을 허용해야 유입이 생깁니다. 본문은 애초에 전송되지 않으므로 색인될 수 없습니다. 구조화 데이터(schema.org/Article + isAccessibleForFree: false)를 넣어 구글의 유료 콘텐츠 정책을 준수합니다.

우클릭 금지·인쇄 차단 같은 조치는 권하지 않습니다. 실효가 없고 정상 이용자만 불편하게 만듭니다.

10

결제 설계

국내 카드 정기결제는 빌링키 방식이 표준입니다. 해외 결제 서비스(Stripe 등)로는 국내 카드사 정기결제를 온전히 처리하기 어렵습니다.

선택지장점유의점권고
토스페이먼츠 직연동 결제위젯으로 카드·간편결제 UI까지 반나절이면 연동. 문서·레퍼런스가 가장 충실. 일반 가맹점 3.4%. 정산 주기는 계약 조건(일/주/월)에 따르며 최소 일주일 — 즉시 현금화는 기대하지 마십시오. 1순위 1인 운영 기준 가장 빠름
포트원 경유 PG를 갈아타도 코드 재사용. 여러 PG 동시 운용 가능. 초기 설정이 복잡. 수수료는 계약한 PG사 기준. 확장 시 해외결제·기관결제 추가 시점에 전환
빌링키는 PG에 종속됩니다. 같은 카드라도 PG사마다 빌링키가 다르므로, 나중에 PG를 바꾸면 기존 구독자에게 전원 재등록을 받아야 합니다. 구독자가 쌓인 뒤 옮기면 이탈이 큽니다. PG 선택은 오픈 전에 확정하되, 향후 이전 가능성이 조금이라도 있다면 여러 PG의 빌링키를 동시 발급해두는 상품(포트원 ‘슈퍼빌링키’ 등)을 처음부터 검토하십시오.
수수료는 매출 구간에 따라 크게 달라집니다. 영세 가맹점(연 매출 3억원 이하)은 2026년 2월 인하로 신용카드 0.40%(체크카드 0.15%)가 적용됩니다. 중소 구간은 3~5억 1.00%, 5~10억 1.15%, 10~30억 1.45%. 일반 가맹점 3.4%와는 자릿수가 다르므로, 초기 매출 규모에서는 수수료가 손익에 거의 영향을 주지 않습니다.

정기결제 흐름

  1. 빌링키 발급구독 신청 → PG 인증창 → 빌링키 수신 → subscriptions.billing_key에 암호화 저장. 카드번호는 자사 서버에 절대 보관하지 않습니다.
  2. 최초 결제빌링키로 즉시 승인 → 웹훅 수신 → payments 기록 → entitlements에 scope='all' 행 생성, expires_at = 다음 결제일 +3일(유예).
  3. 정기 청구Supabase pg_cron이 매일 자정 만료 예정 구독을 조회해 PG 승인 요청. 성공 시 current_period_end 연장.
  4. 실패 처리1차 실패 → past_due 전환 및 이메일 통지 → 3일·5일차 재시도 → 7일차 canceled, 권한 회수.
  5. 해지계정 페이지에서 1클릭. 즉시 차단하지 않고 결제 기간 만료일까지 열람 유지합니다. 해지가 어려우면 분쟁과 민원이 늘어납니다.

항목내용대응시점

콘텐츠 리스크

위험내용대응
높음 타인 저작물 과금 기조연설문, 공저 원고, 기업 자료(팔란티어 등)를 유료 페이월 뒤에 두는 것은 단순 보관과 법적 성격이 다릅니다. §04의 C등급으로 분류해 비공개 업로드 후, 저자·권리자 동의 확보 시 순차 공개. 동의는 이메일 한 통이면 되는 경우가 대부분입니다.
중간 AI 생성 초안 표기 일부 문건은 생성형 AI 초안(그록·제미나이·챗GPT 비교안)을 포함합니다. 유료 콘텐츠에서 출처 미표기는 신뢰 문제로 번집니다. documents에 method 필드를 두고 “AI 보조 작성 · 저자 검증” 등을 문건 하단에 표기.
중간 군 관련 민감 정보 현직 경력 기반 분석은 군사기밀보호법 저촉 여지를 항상 점검해야 합니다. 공개 출처만 인용하는 원칙을 /about에 명문화하고, 발행 전 자체 검토 체크리스트 운영.
낮음 정치적 편향 시비 특정 정부 정책 비판 문건이 다수 포함되어 있습니다. 편집 원칙(사실 기반·반대 논거 병기)을 공개하고, 각 문건에 작성 시점을 명시해 사후 판단과 구분.

위 내용은 일반적인 참고 정보이며 법률 자문이 아닙니다. 통신판매업 신고와 약관은 오픈 전 세무사·변호사 검토를 한 차례 받으시기를 권합니다.
