## 01. 기획 요약

축적된 253건의 전략 분석 문건을 "폴더"가 아니라 "발행물"로 바꾸는 일이다.
핵심은 새 콘텐츠 생산이 아니라, 있는 자산에 **발견 가능성 · 신뢰 표식 · 과금 경로**를 입히는 것이다.

| 지표 | 값 | 비고 |
|---|---|---|
| 초기 카탈로그 | 253건 | 본인 저작 분석보고서 중심 선별 후 순차 공개 |
| 발행 주기 목표 | 주 1~2건 | 현안 발생 시 48시간 내 브리프 |
| 개인 구독가(안) | 12,900원/월 | 연간 결제 시 월 환산 10,750원 |
| MVP 개발 | 8주 | 결제·페이월 포함 4단계 로드맵 |

### 이 플랫폼이 파는 것

안보·국제정세 정보는 공짜로 넘친다. 사람들이 돈을 내는 지점은 정보가 아니라 **판단**이다.
30년 야전·정책 경력을 가진 특정 개인이 "이 사안은 이렇게 읽어야 한다"고 이름을 걸고 말해주는 것 —
이것이 유일하게 방어 가능한 상품이다. 따라서 모든 설계는 *익명의 자료실*이 아니라 *기명(記名)의 판단*을 향한다.

### 설계 원칙 4

1. **기명성** — 모든 문건에 저자·작성일·근거자료를 명시한다. 익명 요약본은 만들지 않는다.
2. **계층 공개** — 핵심 요약은 무료로 완전 공개, 본문·원자료·슬라이드는 구독. 검색엔진에 요약이 노출되어야 유입이 생긴다.
3. **축적의 가시화** — 253건이라는 규모 자체가 신뢰 자산이다. 아카이브 규모와 시계열을 첫 화면에서 보여준다.
4. **단순한 뼈대** — 기능을 늘리지 않는다. 읽기·검색·결제 세 가지만 흠 없이 동작하면 된다.

## 02. 브랜드 체계

'혜안(慧眼)'은 사물의 본질을 꿰뚫어 보는 눈이다. 사건을 나열하는 매체가 아니라
**구조를 읽어주는 매체**라는 포지션을 이름 자체가 선언한다.

| 항목 | 확정안 | 비고 |
|---|---|---|
| 국문 명칭 | **혜안** (한자 병기 慧眼) | 본문·로고 기본 표기 |
| 영문 표기 | HYEAN | 부제 `Strategic Intelligence, Seoul` |
| 한 줄 정의 | 국제정세·안보전략 분석 저널 | 메타 설명·검색 노출문 |
| 슬로건(안) | "현상 너머의 구조를 읽는다" | 대안 — "보이는 사건, 보이지 않는 질서" |
| 도메인 1순위 | hyean.kr | 차순위 hyean.co.kr / hyean.io |
| 이메일 | brief@hyean.kr | 발행 알림·기관 문의 공용 |

### 인장(印章) 마크

로고는 그림 심볼 대신 **낙관(落款) 형식의 인장**으로 간다. 문서에 찍히는 인장은
이 서비스가 파는 것 — 책임지고 서명된 판단 — 을 그대로 은유한다.
정사각 테두리 안에 '慧眼' 두 자, 황동색 단색. 파비콘·워터마크·PDF 헤더에 동일 형태로 재사용한다.

### 디자인 토큰

먹빛 청록(靑綠)과 황동(黃銅). 고문서 표지와 청동 인장에서 온 조합으로,
정부·연구기관 사이트의 관성적인 남색을 피하면서도 경박하지 않다.

## 03. 독자와 가치

네 개 독자층은 지불 의사와 유입 경로가 완전히 다르다. 하나의 요금제로 넷을 다 잡으려 하면 전부 놓친다.
**무료층이 유입을, 실무층이 매출을, 기관이 이익을** 만드는 구조로 설계한다.

| 세그먼트 | 핵심 니즈 | 지불 의사 | 유입 경로 | 역할 |
|---|---|---|---|---|
| **군·정부·정책**<br>현직 간부, 국방·외교 공무원, 국회 보좌진 | 보고서 인용 가능한 구조적 분석. 회의 전 30분 브리핑 | 중 (개인 지출 부담, 기관 결제 선호) | 지인 추천, 강연, 학술제 | 권위 형성 |
| **방산·기업 전략**<br>방위산업, 상사, 금융 리스크팀 | 지정학 리스크의 사업 영향 판단. 대외 발표용 근거 | 상 (법인카드·연간 계약) | 검색, 링크드인, 세미나 | **수익 핵심** |
| **연구자·학계·언론** | 1차 자료 접근, 인용 가능한 원문·도표 | 하 (학생·기자 할인 필요) | 검색, 인용 링크 | 확산·인용 |
| **안보 관심 일반·예비역** | 뉴스보다 깊고 논문보다 짧은 믿을 만한 해설 | 하~중 (1만원대 저항선) | SNS, 커뮤니티, 유튜브 | 트래픽·광고 기반 |

> **가격 벤치마크.** 국내 유료 콘텐츠의 개인 구독 기준선은 월 1만원대 초중반이다
> (아웃스탠딩 월 13,900원 / 연 139,000원, 그룹 구독 5~50인 20% · 50~100인 30% · 100인 이상 40% 할인).
> 혜안은 발행량이 그보다 적으므로 **월 12,900원**으로 살짝 아래에 두고,
> 대신 **아카이브 253건 전량 접근**을 차별점으로 내세운다.

### 문건 유형별 공개 등급

방향은 "전수 탑재 후 단계적 정리"다. 다만 **유료 페이월 뒤에 두는 것**과 **단순 보관**은 법적 무게가 다르므로,
오픈 시점부터 아래 4등급을 DB 필드(`rights_tier`)로 관리한다.
등급은 언제든 상향 가능하되, C·D는 동의 확보 전까지 비공개 상태로 업로드만 해둔다.

| 등급 | 대상 | 초기 처리 | 해제 조건 |
|---|---|---|---|
| **A** | 본인이 작성한 분석보고서·정책보고서 | 즉시 유료 공개 | — |
| **B** | 미 정부 공개 원문 — 2025 NSS, 2026 NDS, Project 2025 | 무료 자료실에 원문 + 본인 해설은 유료 | 원문 자체를 과금 대상으로 삼지 않음 |
| **C** | 타인 명의 저작 — 타 저자 기조연설, 공저 원고, 타인 연구, 기업 자료 | 업로드하되 **비공개** | 저자·권리자 서면 동의 후 공개 |
| **D** | 내부·개인 문서 — 서한, 팀 과제 자료, 미완 초안 | 영구 비공개 | 공개 대상 아님 |

### 발행 형식

| 유형 | 내용 |
|---|---|
| **BRIEF** 현안 브리프 | 사건 발생 48시간 내, 2,000자 내외. 무료 공개 후 7일 뒤 구독 전환. 유입의 주력 |

## 05. 정보구조 · 화면

화면은 6개면 충분하다. 모바일 우선으로 설계하되, 표·도표가 많은 문건 특성상
본문 화면은 가로 스크롤 컨테이너를 기본 제공한다.

### 사이트맵

```
/                     홈 — 최신 브리프 3 + 섹션별 대표글 + 아카이브 규모
/brief                현안 브리프 목록 (최신순)
/topics/[slug]        섹션 7종 (한미동맹, 미국전략, 미중·국제질서 …)
/doc/[slug]           문건 상세 — 요약(공개) + 본문(페이월) + 첨부
/archive              전체 카탈로그 · 필터(섹션/연도/유형) · 전문검색
/pricing              요금제 · 기관 라이선스 문의
/account              구독 상태 · 결제수단 · 영수증 · 해지
/about                저자 이력 · 편집 원칙 · 인용 정책
/admin                발행 · 등급관리 · 통계 (관리자 전용)
```

### 핵심 화면 구성

| 화면 | 위에서 아래로 |
|---|---|
| **HOME** | 최신 브리프 헤드라인 → 섹션 7 그리드 → "253건의 분석" 아카이브 카운터 → 구독 CTA |
| **DOCUMENT** | 메타(섹션·작성일·문서번호) → 제목 → **핵심 요약 전문 공개** → 본문 도입 3문단 → 페이월 → 첨부(PDF·슬라이드) |
| **ARCHIVE** | 섹션·연도·유형 필터 칩 + 전문검색 → 밀도 높은 목록(제목·요약 1줄·날짜·자물쇠 표시) |

| **ACCOUNT** | 구독 상태 배지(다음 결제일 명시) → 결제수단 변경 → 영수증 목록 → **해지 버튼 1클릭 노출** |
| **ADMIN** | Markdown 붙여넣기 → 섹션·등급·공개일 지정 → 첨부 업로드 → 발행. 통계(조회·전환·이탈 지점) |

> **모바일 원칙.** 본문 폭 68자 고정, 표는 개별 `overflow-x` 컨테이너,
> 페이월은 화면 하단 고정 바가 아니라 본문 흐름 안에 배치(iOS 사파리에서 고정 바가 주소창과 충돌).
> PDF는 모바일에서 다운로드가 아니라 **웹 뷰어 우선**으로 열어 이탈을 줄인다.

## 07. 기술 아키텍처

Next.js(App Router) + Vercel + Supabase.
서버를 직접 운영하지 않고, 콘텐츠 보호에 필요한 판단만 서버에서 수행하는 구조다.

```
CLIENT                    VERCEL · NEXT.JS              SUPABASE
─────────────────         ──────────────────────        ────────────────────────
모바일 브라우저     ──→   Server Components      ──→   Postgres + RLS
데스크톱 브라우저          권한 판정 후 본문 렌더        Auth (이메일 · 카카오)
검색엔진 크롤러            Route Handlers                Storage (비공개 버킷)
 (요약만 색인)             /api/webhook · /api/file      Edge Function (워터마크)
                          ISR 캐시 (요약·목록)
                          Edge Middleware         ──→   PG
                          세션 확인 · 리다이렉트         토스페이먼츠 (빌링키)
```

**권한 판정은 반드시 서버(Server Component)에서 수행한다.**

### 선택 근거

| 결정 | 이유 |
|---|---|
| **Vercel Pro 필수** ($20/월) | Hobby 플랜은 상업적 이용이 허용되지 않는다. 유료 서비스는 개설 시점부터 Pro여야 한다. 대역폭 1TB/월 포함 (초과 시 리전별 $0.15/GB~) |
| **Supabase Pro** ($25/월) | Free는 DB 500MB·스토리지 1GB로 PDF 수백 건을 감당하지 못한다. Pro는 디스크 8GB, 스토리지 100GB, 대역폭 250GB 포함 (초과 GB당 $0.09) |
| **본문은 DB에, 첨부는 Storage에** | 본문을 PDF로만 두면 페이월도 검색도 불가능하다. 본문은 Markdown으로 `documents.body_md`에 저장하고, 원본 PDF·PPTX는 비공개 버킷에 둔다 |
| **App Router + RSC** | 권한에 따라 본문을 *보낼지 말지*를 서버에서 결정한다. 클라이언트에서 CSS로 가리는 방식은 개발자도구로 즉시 뚫린다 |

## 08. 데이터 모델

테이블 8개면 충분하다. 구독 상태를 문건 접근 권한과 **직접 연결하지 않고**
`entitlements` 한 겹을 두는 것이 핵심 — 나중에 기관 라이선스·무료 체험·기자단 계정을
코드 수정 없이 얹을 수 있다.

전체 DDL은 `supabase/schema.sql` 참조.

```
profiles       id · email · name · org · role(reader|admin)
categories     id · slug · name_ko · name_en · sort_order
documents      id · slug · title · category_id
               summary_md    ← 무료 공개. 검색엔진 색인 대상
               body_md       ← 유료 본문. 권한 통과 시에만 전송
               doc_type · rights_tier(A~D) · access_level
               published_at · free_until · source_path · tags[]
attachments    id · document_id · storage_path · kind · is_public
plans          id · code · price_krw · period · seats
subscriptions  id · user_id · plan_id · status · billing_key · current_period_end
entitlements   id · user_id · scope · scope_id · source · expires_at
               ↑ 권한 판정은 오직 이 테이블만 조회한다
payments       id · user_id · pg_tx_id · amount_krw · status · paid_at
access_logs    id · user_id · document_id · action · ip_hash · at
```

> **흔한 실수.** 본문을 클라이언트로 다 보낸 뒤 `blur`나 `max-height`로 가리는 구현이 많다.
> 개발자도구 한 번이면 전문이 드러난다. 반드시 **서버에서 본문을 아예 응답에 담지 않는** 방식이어야 한다.

## 09. 콘텐츠 보호

완벽한 복제 방지는 불가능하다. 목표는 **대량 유출을 어렵게 하고, 유출 시 출처를 특정**하는 것이다.

1. **비공개 버킷 원칙** — Supabase Storage 버킷을 private로 두고 공개 URL을 절대 생성하지 않는다. 파일 접근은 `/api/files/[id]`를 거쳐 권한 확인 후 **유효기간 60초 Signed URL**을 발급한다.
2. **개인화 워터마크** — PDF 다운로드 시 Edge Function이 각 페이지 하단에 `혜안 · 홍길동(hong@corp.kr) · 2026-09-01`을 삽입한다. 유출본이 돌아다니면 누구 계정에서 나갔는지 즉시 특정된다. 억지력이 실제 차단보다 크다.
3. **다운로드 한도** — 계정당 일 20건·월 100건. 초과 시 자동 차단 후 관리자 알림. `access_logs`의 `ip_hash`로 계정 공유(동시 다중 IP)를 탐지한다.
4. **본문 서버 렌더** — 권한 없는 요청에는 본문을 응답에 담지 않는다. HTML 소스에도 남지 않는다.
5. **검색엔진 정책** — 요약(`summary_md`)은 색인을 **허용해야** 유입이 생긴다. 본문은 애초에 전송되지 않으므로 색인될 수 없다. 구조화 데이터(`schema.org/Article` + `isAccessibleForFree: false`)를 넣어 구글의 유료 콘텐츠 정책을 준수한다.

우클릭 금지·인쇄 차단 같은 조치는 권하지 않는다. 실효가 없고 정상 이용자만 불편하게 만든다.

## 10. 결제 설계

국내 카드 정기결제는 **빌링키** 방식이 표준이다.
해외 결제 서비스(Stripe 등)로는 국내 카드사 정기결제를 온전히 처리하기 어렵다.

| 선택지 | 장점 | 유의점 | 권고 |
|---|---|---|---|
| **토스페이먼츠 직연동** | 결제위젯으로 카드·간편결제 UI까지 반나절이면 연동. 문서·레퍼런스가 가장 충실 | 일반 가맹점 3.4%. 정산 주기는 계약 조건(일/주/월)에 따르며 최소 일주일 — 즉시 현금화는 기대하지 말 것 | **1순위** — 1인 운영 기준 가장 빠름 |
| **포트원 경유** | PG를 갈아타도 코드 재사용. 여러 PG 동시 운용 가능 | 초기 설정이 복잡. 수수료는 계약한 PG사 기준 | **확장 시** — 해외결제·기관결제 추가 시점에 전환 |

> ⚠ **빌링키는 PG에 종속된다.** 같은 카드라도 PG사마다 빌링키가 다르므로,
> 나중에 PG를 바꾸면 기존 구독자에게 **전원 재등록**을 받아야 한다.
> 구독자가 쌓인 뒤 옮기면 이탈이 크다. PG 선택은 오픈 전에 확정하되,
> 향후 이전 가능성이 조금이라도 있다면 여러 PG의 빌링키를 동시 발급해두는 상품
> (포트원 '슈퍼빌링키' 등)을 처음부터 검토할 것.

> **수수료는 매출 구간에 따라 크게 달라진다.** 영세 가맹점(연 매출 3억원 이하)은
> 2026년 2월 인하로 신용카드 **0.40%**(체크카드 0.15%)가 적용된다.
> 중소 구간은 3~5억 1.00%, 5~10억 1.15%, 10~30억 1.45%. 일반 가맹점 3.4%와는 자릿수가 다르므로,
> 초기 매출 규모에서는 수수료가 손익에 거의 영향을 주지 않는다.

### 정기결제 흐름

1. **빌링키 발급** — 구독 신청 → PG 인증창 → 빌링키 수신 → `subscriptions.billing_key`에 암호화 저장. 카드번호는 자사 서버에 절대 보관하지 않는다.
2. **최초 결제** — 빌링키로 즉시 승인 → 웹훅 수신 → `payments` 기록 → `entitlements`에 `scope='all'` 행 생성, `expires_at` = 다음 결제일 +3일(유예).
3. **정기 청구** — Supabase `pg_cron`이 매일 자정 만료 예정 구독을 조회해 PG 승인 요청. 성공 시 `current_period_end` 연장.
4. **실패 처리** — 1차 실패 → `past_due` 전환 및 이메일 통지 → 3일·5일차 재시도 → 7일차 `canceled`, 권한 회수.
5. **해지** — 계정 페이지에서 1클릭. 즉시 차단하지 않고 **결제 기간 만료일까지 열람 유지**. 해지가 어려우면 분쟁과 민원이 늘어난다.
